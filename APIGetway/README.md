# API Getway

### Описание

API Getway - это сервис предназначенный для приема клиентских запросов и перенаправления их на другие сервисы. Сервис сделан на архитектуре REST API, принимает запросы в формате JSON. Потстроен на фреймворке `Gin` с использованием библиотеки github.com/gin-gonic/gin.
### API эндпоинты

API Getway обрабатывает запросы с эндпоинтами:
- /user/reg;
- /user/auth;
- /markets.
- /order;
- /order/status;
- /order/realtime_status;

#### Регистрация пользователя

Для регистрации нового пользователя через эндпоинт `user/reg` на сервис отправляется запрос в формате *JSON* с полями в теле запроса: 
```json
{
"name":,
"email":,
"password":,
}
```
В поле `name` указывается имя пользователя, далее его `email` и пароль `password`. Все поля являются строками. Пример запроса:
```json
{
"name":"John",
"email":"John001@gmail.com",
"password":"12345."
}
```

После получения запроса, он переадресовывается на сторонний сервис `UserService`. Если данные введены корректно и пользователя с указанным `email` еще не существует в системе, то в ответ на запрос клиент получит токены доступа (`access token` и `refresh token`), благодаря которым сможет использовать и другие эндпоинты.

Пример ответа:

```json
{

}
```

Если `access token` устареет, то при обращении на любой другой эндпоинт кроме `user/auth` токен, как и `refresh token` обновиться автоматически и вернется вместе с ответом сервиса в заголовке. #### Аутенификация пользователя

Аутентификация пользователя происходит на эндпоинте `user/auth`. Данный эндпоинт предназначен для повторного получения доступа к сервисам путем получения новых токенов доступа, когда закончился срок действия токена `refresh token`. Запрос отправляется в формате *JSON* со следующими полями в теле запроса:

```json
{
"email"
"password"
}
```
Пример запроса:
```json
{
    "email":"kate@gmail.com",
    "password":"1234456788"
}
```
Данный запрос переадресуется на сторонний сервис `UserService`. Если `email` и `password` совпадают с данными указанными при регистрации, то в ответ на запрос обновленные токены доступа.

#### Обзор доступных рынов

Для обзора рынков, доступных пользователю используется эндпоинт `/markets`. Данный эндпоинт принимает запрос в формате *JSON* и в ответе возвращает список доступых рынков. Данный запрос перенаправляется на сторонний сервис `SpotInstrumentService`. Так как данный эндпоинт поддерживает пагинацию, то в теле запроса следует указывать максимальное количество рынков, которое вернется в ответе на запрос и если это не первичный запрос, то следует указать токен последнего рынка  из ранее полученного спика, чтобы при повторном запросе получить новый список рынков.

Пример запроса:
```json
{
"page_size":1
}
```
Ответ:
```json
{
"available markets": [
		{
"ID": "97f3a3e5-697c-4991-918b-fc482a03e33d",
"Name": "Upbit"
		}
	]
}
```

Пример вторичного запроса:

```json
{
"page_size":1,
"page_token":"c63c472d-5195-4a7d-9c8f-5ce4f5a0dfd0"
}
```

Ответ:
```json
{
"available markets": [
		{
"ID": "f5af14f1-b078-440a-9caa-ba82a80a415f",
"Name": "TradingView"
		}
	]
}
```

Если не один из рынков для пользователя не доступен, возвращается ошибка с кодом *502*.
```json
{
"error": "error getting available markets"
}
```

При создании запроса, требуется записать в заголовки токены доступа пользователя c соответсвующими именами (`access-token`, `refresh-token`)

Пример:

| access-token  | eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyX2lkIjoiMjQ4Zjc0ZjMtZDkwOC00YTkwLThhZjYtNGRiZjY0YzUzNmJjIiwiZW1haWwiOiJrYXRlQGdtYWlsLmNvbSIsInJvbGUiOiJiYXNpYyIsImV4cCI6MTc4MDI0MjYyMywiaWF0IjoxNzgwMjM5MDIzfQ.iU0d4EKrip7CAfJ3hRljKTowMgAB_cvJz_WDxyCOsBU |

Из данных токенов доступа выделяется информация о идентификаторе пользователя `UserID` и роль пользователя `UserRole`. В соответствии с ролью пользователь получает доступ к тем или иным рынкам.
#### Создание заказа

Для создания заказа используется эндпоинт `/order`. Запрос принимается в формате *JSON*.  Запрос перенаправляется в стронний сервис `OrderService`.Для создания заказа в теле запроса указывается информация, приведенная в примере:
```json
{
"market_id":"de167cc3-126c-48aa-8c8e-9615282c7cb2",
"order_type":"normal",
"price":"134",
"quantity":12
}
```
где `market_id` - номер выбранного рынка, `order_type` - тип заказа, `price` - цена заказа, `quantity` - количество единиц заказа.
Для типа заказа есть 2 варианта: *normal*, *express*.

При создании запроса, так же как и в запросе для получения списка списка доступных рынков требуется указать в заголовке токены доступа для определия прав пользователя и получения его `UserID` и `UserRole`.

При успешном создании заказа, возвращается положительный ответ c кодом *200*.
Пример ответа:
```json
{
"order_id": "1d651582-d574-404d-ad26-259373da8081",
"order_status": "created"
}
```

#### Получение статуса заказа

Для получения статуса заказа используется эндпоинт `order/status`. Запрос перенаправится на сервис `OrderService`.

При создании запроса, так же как и в запросе для получения списка списка доступных рынков требуется указать в заголовке токены доступа для определия прав пользователя и получения его `UserID` и `UserRole`.

Для создания запроса в строке запроса требуется через *query*-параметр указать номер заказа, полученный после успешного создания заказа. *Query*-параметр - `id`.

Пример запроса:
```
http://localhost:8082/order/status?id=1d651582-d574-404d-ad26-259373da8081
```

При существовании номера заказа клиент получит положительный ответ с кодом *200*.
Пример ответа:
```json
{
"market_name": "Binance",
"order_id": "1d651582-d574-404d-ad26-259373da8081",
"order_status": "complited",
"price": "134",
"quantity": 12
}
```
`market_name` - название рынка, на котором был сделан заказ, `order_id` - номер заказа, `order_status` - статус заказа на момент запроса, `price` - цена заказа, `quantity` - количество единиц заказа.

#### Получение статуса заказа в реальном времени

Для. получения статуса заказа в реальном времени используется эндпоинт `order/realtime_status`. Запрос перенаправляется на `OrderService`. Для данного эндпоинта использует *SSE (Server-Sent Events)*.

Для получения статуса в режиме реального времени требуется указать в качестве *query*-параметра номер заказа. *Query*-параметр - `id`. 

Пример запроса:
```
http://localhost:8082/order/realtime_status?id=c6a98327-4570-4558-81a2-d0365b7f86bc
```

Пример ответа:

```json
{
"status": "created",
"update_time": "2026-06-03 20:01:48"
}
```

### Запуск сервиса

Перед запуском сервиса требуется указать `host` и `port` на котором будет запущен сервис и opentelemetry collector. Указываются они в файле `.env`, расположенному по пути:
```shell
./APIGetway/config/.env
```
Пример:

```env
SERVER_HOST = "localhost"
SERVER_PORT = "8082"

COLLECTOR_HOST = "localhost"
COLLECTOR_PORT = "4318"
```

После указания адресов подключения, можно настроить отдельные компоненты работы сервиса в файле конфигурации расположенному по пути:
```shell
./APIGetway/config/config.yaml
```

Пример файла `config.yaml`

```yaml
server:
	port:
	host:
	write_timeout: 10s
	client_connection_timeout: 5s
	request_per_second_limit: 100

breakersetting:
	name: "APIGetway"
	max_request: 5
	interval: 60s
	timeout: 10s
	max_fail_request: 10

collector:
	host:
	port:
	trace_percentage: 100
	metric_interval: 1s
```

Как можно заметить, в данном `yaml` файле поля с названием `port` и `server` пустые. Информация для их заполения берется из переменных окружения обозначенных в файле `.env`.

`breakersetting` - это конфигуратор для настройки *circuit breaker*.

После настройки, сервис готов к работе. Запуск из корня происходит с помощью команды:
```shell
go run APIGetway/cmd/main.go
```

При успешном запуске сервиса в консоле выйдет сообщение следующего содержания:
```shell
2026-06-04T12:35:26.266+0300    INFO    apprunner/fxapprunner.go:318    Server is running on port:8082
```
